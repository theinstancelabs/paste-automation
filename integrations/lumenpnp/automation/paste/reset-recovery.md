# Controller and application restart recovery

A controller power cycle and an OpenPnP application/JVM restart are distinct events; record which occurred and do not describe an application restart as a power cycle. The startup N2 exclusion restore is a model-only operation: `Restore_Paste_Startup_Quarantine.js` consumes a fresh request authored by `prepare-startup-quarantine-request.py`, hash-bound to a pure-model snapshot from the current JVM and the exact live configuration. It accepts the snapshot's explicit enabled state only while unhomed and idle, with the known driver disconnected and N2 already excluded. It backs up disk/live configuration, unsets only N2's manual nozzle-tip-change location, and neither saves configuration nor connects or moves the machine. This does not establish physical position or homing. For example, after a fresh snapshot, prepare a new request with `python3 automation/paste/prepare-startup-quarantine-request.py --source-report .local-machine-backups/paste-live-model-state-<timestamp>/report.json --operator 'Operator name' --review-basis 'Reviewed fresh startup snapshot; authorize only unsetting N2 manual nozzle-tip-change location.' --output automation/plans/paste-startup-quarantine-request.json`.

For a home after an application restart without a controller power cycle, use `mode: "fresh-startup-home"` and `homeReason: "user-requested-home-after-application-restart"`. The request still needs the current JVM/configuration and fresh source, full-route clearance, no-held-part review, and same-frame A/B checks required by the native home workflow. Do not use this reason to imply that power was removed.

## Controller power-cycle recovery

A power cycle invalidates homing and all prior motion, probe and recovery requests even if OpenPnP still displays enabled/homed coordinates. Old controller coordinates are cached values, not physical position evidence. Never replay the interrupted probe or its earlier release action.

`Invalidate_Paste_Reset_State.js` is a narrowly pinned post-reset model action. It verifies the identified dead reader, terminated empty executor, current configuration and unchanged cached coordinates, and saves verified private live/disk backups. It disconnects the native driver first, verifies the port is closed, and only then disables/unhomes the machine. Live actuator disable callbacks must all be `LeaveAsIs`; head pump actuators must be absent. It replaces only the terminated empty executor, starts no worker, submits no task, and never restores old coordinates or homing. It sends no controller command and does not reconnect.

The separate staged `Reconnect_Paste_After_Reset.js` accepts an explicit fresh `automation/plans/paste-reset-connect-request.json` based on the unusable pending template. It binds the successful invalidation artifact, same JVM/configuration and cached state. It verifies the reviewed by-id device and lack of any other serial owner before using the existing native driver. Native connection sends its audited G21/G90/VAC-sensor initialization; it does not enable or home. M115/M503 and fresh M114 responses are retained and checked. Only after the fresh position report and its following ACK are received does the script synchronize the complete native model from that controller frame. This uses native `AxesLocation.setToCoordinates`, not G92 or restored old coordinates.

Success leaves the native connection open, machine disabled and unhomed. The reported reset frame is synchronized but absolute physical position remains unknown. Motion is a separate reviewed action. In particular, firmware `Z_SAFE_HOMING` may move XY before a Z home; do not infer that `G28 Z` raises the heads first. A potential unhomed raw-Z clearance jog requires fresh reset-frame synchronization, separately reviewed physical clearance and native API checks. This recovery performs no jog or home and establishes no paste calibration.

`Home_Paste_After_Reset.js` performs a separately reviewed native home only after fresh whole-route clearance. Its response audit keeps the normal G28 position echo as prior evidence and requires a new M114 report with its following ACK before synchronizing coordinates or enabling. A G28 echo can never substitute for that fresh query.

`Finalize_Paste_Home_After_Report.js` handles only the exact recorded failure where G28 and M400 completed but the audit rejected G28's ordinary position echo before sending M114. It never homes, moves, enables, or invokes planner completion. It uses the existing native owner for a fresh M114, verifies all five axes and the following ACK, synchronizes model/driver caches, and releases only the proven dead-empty executor quarantine. It remains disabled and unhomed: a firmware coordinate report cannot establish physical position after prolonged unobserved idle or possible stepper release. A later home requires a separate fresh request and image, a reviewed full physical homing envelope, and the explicit `deliberate-rehome-after-prolonged-idle` reason. None of these operations restores board registration or establishes paste calibration.

## Operator home after a laptop restart

An operator-completed home can now be checked with `capture-manual-home-position.py --operator-home-confirmed`. It reads the live model and requests an M114 position barrier through the existing owner; it does not home or move. Restore the N2 manual tool-change exclusion first if startup initialized it. The restore authorer has an explicit `--restore-variant manual-homed-connected-idle` option for that model-only change, with private backups and unchanged disk configuration.

The separate manual-home ledger-anchor proof admits historical accounting only after the unchanged syringe ledger, B position/count, and configuration lineage are checked. It does not reuse board registration or old motion coordinates. Fresh registration, current profile reviews, and per-batch preview remain necessary. An operator home can legitimately update N1 runout compensation and the left rotation position.

Linear count verification compares signed step-count changes, with a one-step rounding allowance and exact unchanged counts on other axes. It no longer assumes that firmware raw-coordinate zero is motor-count zero after native homing. Extruder B retains the existing absolute count check. This software change does not establish paste quality or authorize replay of a stopped batch.
