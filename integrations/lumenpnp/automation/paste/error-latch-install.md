# In-memory native error-latch installation

`paste-error-latch` routes to `Install_Paste_Error_Latch.js`. The action requires a fresh explicit request in `automation/plans/paste-error-latch-request.json`, bound to the exact current JVM, live serialized configuration and disk `machine.xml` hashes. The supplied pending template cannot authorize anything. Parent source review precedes dispatch.

This is a no-motion native configuration edit, not a firmware command. It requires the audited driver/JAR, connected live reader, idle single-worker executor, no queued/subordinate motion or pre-existing error, stopped job, empty heads and N2 quarantine. The previous error command must truly be absent, including empty/scoped variants. Callers cannot supply a replacement regex or command: only `NativePasteAir.nativeErrorRegex` is installed.

Before mutation, an exclusive private UUID directory stores verified disk and serialized-live backups and the prior null value. A fresh command list copies the existing entries and appends a fully constructed native command. Publishing that list through the existing driver's public reference avoids modifying an ArrayList while its reader iterates it. No connect, send, position query, actuator operation, save or motion API is called. Getter readback, post-edit serialization/hash, unchanged raw/driver coordinates and unchanged disk hash are recorded. On failure, the original list is restored only if the replacement is still the active list; concurrent changes are never blindly overwritten. The native error cache is never cleared.

The installed reader resolves the error regex on every received line. The command-list reference is not volatile; getter readback alone is not proof of reader-side publication or fault handling. A separately reviewed read-only position/ACK barrier and activation review are required before any motion. The native `bailOnError` clears the cached error as it throws, so this configuration is not a durable fault lock; executor-level no-retry handling remains necessary. Native ACK matching occurs before error matching for a single line, so tests of ordinary separate error/ACK lines do not establish race-free behavior for a corrupt combined ACK/error line.

Backups and reports remain local, never part of the source export. A successful in-memory edit changes the live configuration hash and invalidates all previously prepared motion requests. It does not establish calibration, collision clearance, deposition readiness or persisted configuration. No firmware flash, save or restart is implied.
