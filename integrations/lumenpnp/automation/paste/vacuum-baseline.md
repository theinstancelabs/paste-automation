# Stationary N1 free-air baseline recorder

`Record_Paste_Vacuum_Baseline.js` is staged behind the reviewed `paste-vacuum-baseline` route. It performs no motion, homing, Z approach, rotation, pickup, motor-current change, pressure-threshold calibration, or extrusion. No live request is provided. Copy the pending request to a new private request only after parent/operator review of exact current JVM, configuration hash, raw/driver/native poses, installed N1 tip identity, and a fresh image showing empty nozzles and free-air clearance. The image/request lifetime is five minutes. The request path is `automation/plans/paste-vacuum-baseline-request.json`; each UUID claims its evidence directory once, preventing replay.

The sequence acknowledges VAC1 off, settles, records off samples, acknowledges VAC1 on, settles, records free-air samples, then acknowledges normal off. Sample counts and timing are bounded operational controls; no pressure threshold is assumed. It records individual byte readings, timings and descriptive min/max/mean/spread. These do not establish a seal, contact Z, nozzle condition, safe descent floor, or a calibrated paste profile. The pending JSON contains null measurements and false physical attestations.

The existing native OpenPnP driver remains the sole owner. The audited `actuatorRead` hides its consumed response list, and direct boolean `actuate` sends both configured lines before an external error check. Consequently this recorder uses the **exact validated existing VAC1 templates** through that driver's bounded `sendCommand`/response queues, checking every response before the next allowlisted line. There is no arbitrary command input. It awaits ACK in the full response queue as well as the driver's confirmation queue, preserving the reader's ACK delivery race; a delayed M261 value is collected with all intervening lines. Error/reset/resend/disconnect, missing or unexpected pressure data, timeouts and elapsed-duration overruns stop further commands. Fixed VAC1 command ACK and response waits are each bounded at 3000 ms. Native `getReportedLocation(3000)` is different: its M114 ACK uses the driver's native infinity-timeout setting (verified finite and at most 60000 ms here), followed by a 3000 ms position-report poll and bounded full-response collection. Each position query retains the complete response queue through a fresh position-report delimiter and its following ACK, so earlier ACKs cannot stand in for query completion. The same live reader and command-list identities, exact native error/position patterns, empty subordinate queue, immutable saved coordinates and unchanged live configuration are required throughout. Both position queries are outside the recorder's vacuum-on sampling phase. The report records these limits. A currently blocked command may finish after the overall sampling deadline, but no later VAC1 command follows it.

The runner preserves the reviewed single-worker executor ownership and GUI responsiveness without generic machine-task completion or actuator coordination, which could wrap rotary coordinates. It checks exact poses before actuation and each command, and compares independent M114 before/after readings on all five axes. It saves raw stationary camera images before and after. Runtime actuator caches are not modified: acknowledged command state is recorded separately, rather than treating a stale UI indicator as evidence.

A fault does not send an automatic cleanup off, retry, or motion command. Vacuum may remain on; the report records its last acknowledged state and uncertainty. The current executor is stopped and its busy marker retained after a controller-query, actuation or transport fault; this guards the reviewed dispatcher and busy-sensitive UI, not arbitrary direct native submissions. Separate supervised inspection/recovery is required. Normal acknowledged completion ends with vacuum off. Software tests and compilation do not establish physical vacuum behavior.

Offline checks: `node --test automation/paste/vacuum-baseline.test.cjs`. Native scripts must only be compiled for syntax during software review, never evaluated as a test.
