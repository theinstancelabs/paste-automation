# Disabled native air adapter replacement

`Run_Paste_Air.js` remains code-disabled before any native API access. This replacement removes the former public machine-task wrapper, N2 movement and N2 completion calls. No hardware execution, motion, driver setting change, measured profile completion, or commissioning result is established by this change.

The existing offline plan schema remains unchanged. `session.pending.json` adds a `nativeExecution` contract: exact full raw/driver and N1/N2/top/bottom native starting poses, fresh clearance-image hash, reviewed complete swept-path record, explicit X/Y order, bounded segment size, and exact SHA-256 of the serialized segment list produced by `NativePasteAir.segments(spec)`. The parent must obtain native transforms from a separately reviewed read-only planning step once actual tip-frame calibration exists; the runtime never fills missing measurements or silently authorizes its computed path. All initial and intermediate path segments, both heads, syringe, tubing and nearby objects must be reviewed, including the L-shaped corners rather than only placement endpoints.

The adapter transforms every measured N2-frame target into raw controller coordinates with constant Z/A/B, then uses partial raw targets containing exactly one X or Y axis. It preflights every segment, measured raw bounds and native reachability. Each segment is at most the explicitly reviewed maximum, capped at 10 mm. It requires the exact installed NullMotionPlanner and minimum speed 0.05, and accepts only speed fractions 0.05–0.1. `SpeedOverPrecision` bypasses the audited one-sided backlash overshoot; nonzero directional offsets, subordinate queued axes, actuator interlocks or changed mappings reject execution.

Execution uses the existing single-worker executor with explicit ownership/busy bookkeeping. The top camera must map only physical X/Y; native completion therefore does not wrap B. No generic completion, lift, home, park, nozzle tool operation or serial connection is used. Full native configuration identity, measured offsets and current supervised session remain checked. Every segment completes and passes independent firmware-position verification before another can begin. Z/A/B remain invariant, including an unwrapped B value such as 720; reporting tolerance is not permission to command them.

Native motion can emit optional M204 acceleration setup and a G1 line before M400. Therefore post-return response inspection alone cannot stop a second native line after a first-line fault. **Activation additionally requires the exact reviewed `NativePasteAir.nativeErrorRegex` to be active as the driver's `COMMAND_ERROR_REGEX`.** An absent setting is rejected; this adapter does not install or change it. A separate reviewed no-motion installer and position barrier handle that prerequisite. The proposed pattern has native Java matching tests, but live latch behavior, configuration backup/application and measured-profile revalidation still require separate review. A nonempty or merely similar error regex is not accepted. The completion-response regex must remain absent because it otherwise consumes responses invisibly.

The adapter preserves all available motion and completion responses, inspects faults before the next query, and uses a fresh M114 position-report line followed by its own ACK as a response delimiter. It does not assume a fixed count of motion ACKs or that a tiny native step necessarily emitted a line. Immutable model/driver snapshots precede every query. Independent before/after firmware coordinates are compared with the exact planned start, target and delta. Native M114's ACK timeout can be up to 60 seconds, plus bounded report/queue waits; the report records that distinction. The GUI remains responsive, but blocked native commands are not a software emergency stop.

Pause/cancel is checked before the first move and at every verified joint-clearance segment boundary. No lift is inferred. A paused run ends and requires a fresh reviewed remaining-path plan/session; claims cannot be replayed. Any attempted-move or query fault retains a stopped-executor/busy latch and records uncertainty, without further motion or cleanup. This gate does not intercept arbitrary direct native submissions. Source plans and response records are software evidence, never proof of collision clearance or successful paste deposition.

Offline verification uses independent mock traces in `native-air.test.cjs` and installed-Nashorn syntax compilation plus Java fault-pattern cases in `test_native_air_nashorn.py`. The latter compiles the runtime without evaluating it. No fake calibrated profile or live request is included.
