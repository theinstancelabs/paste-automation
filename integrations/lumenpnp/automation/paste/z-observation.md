# Guarded one-step raw Z observation

`paste-z-observe` routes to the separately reviewed `Observe_Paste_Z.js` adapter. Its narrow source activation permits only the exact request contract; no usable request is bundled. It does not establish a measured joint clearance profile, surface height, optical focal plane, extrusion behavior or calibration.

The schema-2 pending request allows exactly one signed raw Z increment selected from −5, −1, +1 or +5 mm. Its physically reviewed interval must equal the complete start-to-target segment; no larger global application envelope is inferred. A fresh hashed image and explicit review record must confirm both heads, extruder, camera, tubing and surrounding objects for the exact pose and swept step. Every step requires its own UUID and evidence; there is no automatic continuation or return.

The request binds actual native Z soft-limit and safe-zone values and their enabled flags. Runtime reads those getters before execution, rejects changes and enforces any enabled soft limit. Disabled soft-limit values are recorded but never interpreted as travel bounds. Safe-zone values do not establish travel limits or collision clearance. The legacy 26.5–36.5 mm safe zone therefore does not authorize motion outside or inside it by itself.

A successful, hash-verified read-only position barrier from the same JVM/configuration must be at most five minutes old; its terminal raw/driver/native snapshots exactly match the requested start. The request binds the current JVM, serialized configuration, immutable five-axis raw/driver snapshots and both head/camera native poses. The image and request also expire after five minutes. Missing measurements or attestations fail closed.

Installed API review confirms a partial raw Z target can pass through the existing NullMotionPlanner with the top camera as completion context. The top camera maps only X/Y to the same sole driver; completion waits for pending Z while avoiding any physical rotary mapping. The requested target contains exactly Z. No N2 move, nozzle completion, generic machine-task wrapper, lift, return, vacuum, current command or serial connection is used. The native executor remains the only worker and the GUI remains responsive.

Speed remains at native fraction 1.0 with the audited Z feed limit of 200 mm/s; controller acceleration and trajectory limits still apply. This setting does not establish a noncontact gap or permission to approach a surface. The exact Z axis/type, DirectionalCompensation method with zero backlash and sneak-up offsets, zero current directional offsets, empty motion/subordinate queues, no actuator interlocks, N2 quarantine and unchanged controller templates are required.

As with the disabled air adapter, the native per-line error/reset latch must match the reviewed error pattern. The independently reviewed installer may provide this setting in memory; the fresh bound position barrier verifies the post-install state. Absence or a changed setting blocks execution. The script does not install it or change any driver setting. Full motion/query responses are retained and audited using an M114 position-line delimiter followed by its own ACK. Model and driver coordinates are copied before every query. The independent firmware reports must show only the requested Z delta; X/Y/A/B, including B720, stay unchanged. Before motion, read-only native transforms of the full start and target must predict the same coupled polarity, with no other pose changes. Native N1 Z must change by the signed raw increment and N2 Z by its negative; top/bottom native camera poses stay unchanged. These checks test configured kinematics and reported motion, not physical displacement measurement.

Before/after raw camera images and contact sheets are saved after bounded settling. Each UUID claims a new record once; completed or failed claims cannot be replayed. Any uncertain query or attempted-motion fault stops the existing executor and retains the busy marker without return or recovery motion. This guard covers reviewed and busy-sensitive paths; arbitrary native submissions can recreate an executor. A successful record still requires visual review of actual movement, polarity and clearance. No automatic calibration or configuration correction follows.

Offline checks: `node --test automation/paste/z-observation.test.cjs` and `python3 -m unittest discover -s automation/tests -p test_z_observation_nashorn.py`. The latter compiles runtime and policy with installed Nashorn without evaluating machine code.


Fine signed 0.1, 0.25 and 0.5 mm choices are enabled by `PASTE_FINE_Z_OBSERVATION_ENABLED = true`; each still requires `reviewedFineZStep: true`. They retain every fresh barrier, exact local interval, image, native snapshot, full-speed setting and both-head clearance gate. Smaller distance does not establish a noncontact surface gap.

For a fine step, both retained M114 response sets must contain exactly one complete integer `Count X/Y/Z/A/B` payload. Before motion, the starting count payload must already be present. Afterward, the reported controller-count difference must be exactly ±4, ±10 or ±20 on Z for the reviewed 40 steps/mm setting, with zero count change on X/Y/A/B. Missing/duplicate count payloads or a single discrepant count stop the adapter without a subsequent motion. These are controller step counters, not encoders: they do not prove physical motor travel, tip gap or contact. Existing reported-coordinate and native-pose checks also remain in force. No extra controller query or firmware setting change is introduced.


Fine requests require `reviewedFirmwareZStepsPerMm: 40` and a hashed absolute-path evidence file. Evidence can be either reviewed same-session firmware settings (`firmwareSettingsEvidence`, including acknowledged M503/M92 Z40 and configuration lineage) or a completed same-JVM Z observation (`firmwareStepEvidence`). The latter must match the request's JVM and serialized configuration, have verified completion and independent position, and show an exact Z controller-count delta of `deltaMm × 40` with X/Y/A/B unchanged in its retained before/after M114 responses. Reported positions and saved snapshots must agree. This controller-count evidence establishes the firmware step scale only; it is not an encoder measurement or proof of physical displacement. It requires no reconnect or extra controller query. Current pose, image and barrier freshness checks remain unchanged.
