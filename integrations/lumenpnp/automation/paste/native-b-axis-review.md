# Native B prerequisites — configuration only, no dispensing adapter

Installed API inspection found that the existing B axis is modeled as Rotation with `limitRotation=true`, `wrapAroundRotation=false`, and `invertLinearRotational=true`. The native planner's `limitAxesLocation` processes every requested axis. For B it calls `limitRotationAxis`; when the supplied top camera does not move B, the limiter substitutes B's default mountable, N2. With rotational soft limits disabled, the limiter uses a default ±180° range and adjusts by full turns. A requested absolute target near 720 can therefore become a target near zero. Top-camera completion avoids later rotary wrapping, but does not prevent this earlier target normalization.

A future native dose path must preserve the current unwrapped B coordinate and request only a bounded delta from that coordinate. It must not reset B or use N2 motion/completion helpers. After rotation limiting is disabled, with wrapping still false, the installed planner skips both rotational target transformations. That is a necessary prerequisite, not proof that extrusion direction, stroke, pressure, delivered volume or mechanics are safe.

The previous native B feed limit is 50000 units/s. The installed planner clamps speed fractions below 0.05, so an arbitrarily small fraction cannot guarantee a slow dose. `invertLinearRotational=true` makes B non-rotational for controller feed accounting; it does not invert the sign or change the raw B coordinate. The installed driver formats a Rotation axis target directly from `AxesLocation.getCoordinate(B)`; it does not apply linear-unit conversion to that target. Its feed metric classifies B as linear, while squaring displacement magnitude for the metric leaves the signed absolute B target unchanged. Thus the in-memory `Length` unit label is a native rate convention, not a conversion of syringe rotation into millimeters. Treat firmware B units as an explicitly verified controller contract, not an automatic physical angle or encoder measurement.

The reviewed `paste-b-config` action uses `Configure_Paste_B_Axis.js` to change exactly two in-memory fields: B `limitRotation` from true to false and B feed limit from 50000 to 100 units/s. A 0.05 native fraction then gives a nominal ceiling of 5 B units/s before acceleration and trajectory constraints. This is a commissioning candidate, not measured paste-flow calibration. Wrapping remains false; acceleration, jerk, controller current, firmware settings, all other axes and coordinates remain unchanged.

The action binds a fresh successful read-only position barrier, exact JVM/configuration/disk hashes and full starting poses. It uses the existing native single worker, verifies private serialized-live/disk backups before editing, and requires the entire serialized after-state to equal the before-state with exactly those two B fields changed. It verifies readback, coordinates and unchanged disk bytes. On failure it restores the two original values only when the state matches the expected edit or its first-field intermediate state; a concurrent unexpected change is not overwritten. No query, motion, connect, save, current command or coordinate reset is issued.

A successful edit invalidates prior motion requests because the live configuration hash changes. A separate fresh position barrier accepts the exact completed B configuration record and establishes stationary state before further work. Configuration success never authorizes extrusion. A later adapter still needs verified sign, usable syringe stroke, priming over an identified waste target, bounded absolute B targets and speed, per-command response and position verification, plus a separately reviewed response to pressure or transport faults. No such adapter is enabled by this change.

## Isolated native mathematical fixture

Run `python3 -m unittest automation.tests.test_native_b_axis` from the automation repository. `tests/java/CheckNativeBAxis.java` constructs fresh, disconnected objects; it never loads machine configuration, invokes machine motion, or opens communications. A millimeter conversion shim avoids global configuration access. With wrap and limit flags false, the installed planner's real `limitAxesLocation` preserves partial B targets 719, 720 and 721; merging each into a synthetic full location preserves XYZ/A. An enabled-limit sentinel verifies that the limiter branch would otherwise run; this fixture does not claim to reproduce its complete nozzle-dependent wrapping transform.

The installed native `Motion` calculation for a synthetic one-unit B step, feed limit100, acceleration500, jerk2000 and fraction0.05 returned approximately0.8333 units/second with a fresh default driver. This is an isolated fixture result, **not a live rate prediction**. Five units/second is the nominal feed-limit ceiling from100×0.05; actual motion profiles and the installed driver's motion control type may reduce or interpret the emitted rate. A future B motion adapter must inspect its actual projected native command/rate and preserve all other axes before physical commissioning.
