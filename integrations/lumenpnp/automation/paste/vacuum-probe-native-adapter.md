# Guarded native N1 VAC1 probe adapter

`Probe_Paste_Surface_By_Vacuum.js` is registered as `paste-vacuum-probe` after source review and offline checks. Each execution still requires an explicit fresh request satisfying every state, target, clearance, sensor and evidence gate. No usable request is included. The adapter has not been physically commissioned; software activation does not establish contact or calibration.

The adapter reuses the current OpenPnP owner, audited one-worker executor, camera-context partial raw-Z move, native completion, response/error checks and N2 quarantine checks reviewed for the single-step Z observer and stationary VAC1 baseline. It sends only the current exact VAC1 command-template lines through the established GcodeDriver. It never calls actuator `read()`/`actuate()`, which would coordinate with machine axes, and it opens no second serial transport. A sampled pressure value is paired with a pre-query raw/driver/native snapshot, full M114 response, and post-query stationary comparison before the policy can choose a next step.

The pending request schema is `vacuum-probe-native.pending.json`; it is intentionally unusable. Execution requires the exact current configuration/JVM, a fresh no-motion position barrier, fresh images, explicit target-surface identity, an exact reviewed full coupled Z interval for this pose, both-head clearance attestations, no held parts, current empty N1 tip identity, quarantined N2, and a five-minute bound. The full candidate descent segment must be explicitly reviewed. The command remains partial raw Z only with X/Y/A/B fixed, using the top-camera completion context and existing executor; no generic nozzle motion, `moveToSafeZ`, pickup, tool-change, probing helper or competing serial connection is used.

The runtime contract limits the total descent to at most 2.00 mm and each increment to exactly 0.05 mm. The current firmware evidence is 40 controller steps per mm, so a move should change the Z counter by exactly two steps; the adapter checks the M114 count delta on each acknowledged step. The native planner minimum remains 0.05. The request may explicitly select legacy motion fraction 0.05 (10 mm/s nominal feed ceiling) or full motion fraction 1 (200 mm/s nominal feed ceiling) from the configured 200 mm/s raw-Z ceiling, before acceleration/trajectory effects. The selected fraction is recorded in the request, report, and each move. Full speed applies only to each independently gated 0.05 mm increment; all sample, position, counter, floor, and stop checks remain in force. This is not a calibrated touch move. The complete coupled sweep and current upper mechanical envelope must be reviewed for the exact starting pose.

The reviewed stationary free-air record showed VAC1 at 255 with the pump off and a mean of 232.25 (spread 1) with it on. Before any descent, the runner takes three fresh off samples and eight fresh on samples, requiring off spread ≤1, on spread ≤1, on mean within 1.5 counts of 232.25, and at least a 10-count off/on difference. This catches disconnected or ineffective vacuum sensing before motion. It then uses the eight on samples as a fresh baseline, with one count of noise allowance; two successive readings each at least four counts below baseline stop at a **seal candidate**. This evidence is only a free-air pump/sensor baseline, not a surface-contact threshold: it does not establish response to an empty needle touching the target, hard contact, surface height, or paste readiness.

The pure policy authorizes only one incremental raw-Z target after a complete quiet sample window. The first deviation holds the same Z for one confirmation sample; sustained candidate response stops at that same Z. Partial/mixed or opposite-sign response, baseline instability, sensor/transport error, timing violation or reaching the bounded floor fails closed. No additional compression follows a deviation. Every 0.05 mm move must complete through the existing planner and independently pass raw/driver/native pose checks, firmware M114 checks and the exact two-counter-step check before its position can be acknowledged to the policy.

After a seal candidate, or after an explicit measurement-only rejection (unstable/mismatched empty baseline, ambiguous/partial response, opposite-sign response, or no seal at the reviewed floor), the adapter may send the existing VAC1-off lines only when the current transport is certain, the last position is independently verified, and reader/error/configuration/driver/queue/N2-quarantine/held-part checks still pass. It then obtains a fresh M114 and repeats those checks. Only successful OFF acknowledgment and final position verification allow the existing executor task to end normally and clear its busy state. It holds Z where the policy stopped and does not retract, lift, retry, compress, or automatically recover. Sensor/transport/controller/motion faults, uncertain state, failed OFF, or failed final M114 do not trigger another command; the executor/busy latch remains for supervised recovery. That latch cannot prevent arbitrary manual UI/native submissions. Candidate completion still requires human image/evidence review and repeated independent contact observations before any Z calibration. The script never changes nozzle or paste calibration.
